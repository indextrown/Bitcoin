# V4.1 추세 필터 RSI 회복 전략

V4.1은 V4의 RSI 회복 매수를 유지하면서, 하락 추세에서 생기는 일시적 반등 진입을 줄이려는
실험 전략이다. 폴더 이름은 Python import 경로 때문에 `v4_1`을 쓰고, 전략 이름은 V4.1로 표기한다.

기본 대상은 `KRW-ETH`, RSI와 추세 판단 기준 봉은 4시간봉(`minute240`)이다.

## 매매 규칙

| 구분 | 기본값 | 의미 |
| --- | ---: | --- |
| RSI 회복 매수 | 이전 RSI `< 40`, 현재 RSI `≥ 40` | 과매도권에서 벗어나는 순간만 진입을 검토 |
| 추세 필터 | 현재가 `≥ SMA(50)` | 4시간봉 종가 50개의 단순이동평균 위에 있을 때만 매수 |
| 매수 비중 | 가용 원화 100% | RSI 회복과 추세 필터가 모두 맞으면 전액 매수 |
| 익절 | 수익률 `≥ +3%` | RSI와 관계없이 전량 익절 |
| 손절 | 수익률 `≤ -5%` | RSI와 관계없이 전량 손절 |
| RSI 청산 | RSI `≥ 75` | 익절·손절 전이라도 전량 청산 |
| 손절 쿨다운 | 24시간 | 손절이 체결된 뒤에는 새 매수를 24시간 동안 막음 |
| 최소 주문 | 5,000 KRW | 업비트 최소 주문 금액보다 작으면 주문하지 않음 |
| 수수료 가정 | 주문당 0.05% | 백테스트의 매수·매도에 각각 적용 |

```text
이전 4시간 RSI < 40, 현재 RSI ≥ 40
                  +
현재가 ≥ 4시간봉 SMA(50)
                  ↓
               전액 매수
                  ↓
 -5% 손절 ──┬── +3% 익절 ──┬── RSI 75 이상 청산
             ↓               ↓
                        전량 매도
             ↓
        24시간 재진입 금지
```

`SMA(50)`은 최근 50개 4시간봉 종가의 평균이다. 약 8.3일 동안의 평균 가격보다 현재 가격이
높은 경우만 RSI 회복 매수를 허용한다. 이 조건은 가격이 하락하던 중의 짧은 반등을 줄이려는
필터이며, 상승을 보장하지는 않는다.

## V4와의 차이

| 항목 | V4 | V4.1 |
| --- | --- | --- |
| 진입 | RSI 40 회복 | RSI 40 회복 + 현재가가 SMA(50) 위 |
| 손절 | -10% | -5% |
| 손절 뒤 재진입 | 제한 없음 | 24시간 쿨다운 |
| 올해 동일 구간 체결 | 39회 | 4회 |

V4.1은 진입을 훨씬 적게 한다. 높은 수익 기회를 모두 잡으려는 전략보다, 긴 하락 구간에서
포지션을 잡지 않아 최대 낙폭을 줄이는 데 초점을 둔다.

## 백테스트 결과와 한계

2026-01-01~2026-08-02, 60분 크론 가정, 다음 원본 봉 시가 체결, 주문당 0.05% 수수료 기준이다.

| 전략 | 총수익률 | 최대 낙폭 | 체결 수 |
| --- | ---: | ---: | ---: |
| V4 | +5.64% | -21.07% | 39 |
| V4.1 | +6.38% | -2.43% | 4 |

V4.1은 이 구간에서는 V4보다 높은 수익률과 낮은 최대 낙폭을 보였다. 하지만 실제 체결은 4회뿐이고,
SMA(50) 조건을 만족한 시점이 주로 6월 이후에 몰려 있다. 1~4월 연구에서는 SMA(20)를 사용한
다른 후보가 더 좋았다. 따라서 이 결과만으로 V4.1이 언제나 우수하다고 판단하거나 실제 crontab에
등록하면 안 된다.

## 백테스트 가정

- 기본 크론 가정은 60분이다. 실제 서버 실행 주기는 crontab이 정하며, `btc_bot.py`는 이 값을 읽지 않는다.
- 60분 원본 봉으로 매 실행 시점의 부분 4시간봉 RSI와 SMA를 다시 계산한다.
- 신호는 해당 원본 봉 종가까지의 정보만 사용하고, 주문은 다음 원본 봉 시가에 체결된 것으로 계산한다.
- 손절 주문이 체결된 시각부터 쿨다운을 계산한다.
- 원본 OHLCV는 `develop/v3/backtesting/cache/`의 공용 캐시를 재사용한다. 전략별 결과와 실제 거래 상태는 공유하지 않는다.

## 실행

```bash
# V4.1 기본 설정으로 PNG 생성
make backtest v4_1

# 기간과 실제 체결 RSI 점을 지정해 PNG 생성
make backtest v4_1 FROM=2026-01-01 TO=2026-08-02 SHOW_RSI_SIGNAL_POINTS=1

# SMA 기간·손절·익절·쿨다운 후보를 같은 체결 가정으로 비교
python3 develop/v4_1/research.py --from 2026-01-01 --to 2026-08-02 --cron-interval-minutes 60

# 실제 주문 실행. trade_state.json으로 손절 쿨다운을 이어가므로 crontab 등록 전에는 실행하지 않는다.
python3 develop/v4_1/btc_bot.py
```

## 테스트

```bash
# 추세 필터·쿨다운·상태 파일·백테스트 순수 로직 테스트
python -m unittest discover -s develop/v4_1/tests -p 'test_*.py' -v
```

## 파일 역할

- `config.py`: 티커, RSI·SMA·손익 관리 기준, 백테스트 가정
- `trade_logic.py`: API 호출 없는 RSI 신호·추세·쿨다운·매매 판단 순수 함수
- `trade_state.py`: 실제 봇의 최근 손절 시각을 JSON으로 저장·복원하는 도구
- `btc_bot.py`: 실제 업비트 주문, 알림, 자산·거래 로그, 손절 상태 저장
- `backtesting/backtest_logic.py`: 크론·수수료·다음 봉 시가·손절 쿨다운을 가정한 순수 시뮬레이터
- `backtesting/backtest_visualizer.py`: V4.1 설정과 결과를 표시하는 PNG 생성기
- `research.py`: SMA·손익 관리·쿨다운 후보를 같은 체결 가정으로 비교하는 연구 도구
- `tests/`: 매매 판단, 상태 저장, 백테스트 단위 테스트
